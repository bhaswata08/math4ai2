Act 5 of 6

Automatic differentiation

Not symbolic, not numeric: the chain rule, applied to a recorded computation.

Act 5 / The thing we are replacing

Bump and revalue

The obvious way to get a derivative from code: nudge one input by \(\delta\), run the function again, divide.

$$\frac{\partial f}{\partial x_i} \;\approx\; \frac{f(x + \delta e_i) - f(x)}{\delta}$$

Truncation error

The Taylor series has a tail, and this throws it away. The answer is approximate however carefully you pick \(\delta\).

One bump per input

Every \(x_i\) needs its own revaluation, so a gradient over \(n\) inputs costs \(n\) extra runs of the whole function.

Autodiff fixes both: exact to machine precision, and for a gradient, a cost that does not grow with \(n\).

Break \(f\) into operations you already know

  • Follow every place \(a\) appears: \(\sin a\), then times \(b\), then plus \(b^2\).
  • Every step is an operation whose derivative you know by heart.
  • The chain rule is then a product of three factors, and you may multiply it from either end: right to left is forward, left to right is reverse.
Act 5 / Two directions, two names

The same product, multiplied two ways

$$\frac{\partial r}{\partial a} \;=\; \underbrace{\frac{\partial r}{\partial w_1}}_{\text{last step}}\;\frac{\partial w_1}{\partial w_0}\;\underbrace{\frac{\partial w_0}{\partial a}}_{\text{first step}}$$

Forward, or tangent mode

Start at the input end. Fix the denominator: every quantity you carry is \(\partial(\cdot)/\partial a\), written \(\dot{(\cdot)}\).

Reverse, or adjoint mode

Start at the output end. Fix the numerator: every quantity you carry is \(\partial r/\partial(\cdot)\), written \(\overline{(\cdot)}\).

A dot means "with respect to a chosen input". A bar means "of a chosen output". AAD is adjoint autodiff, the reverse one.

Forward mode: a tangent beside every value

  • Primal and tangent computed in parallel, row by row.
  • The seed picks the input: \(\dot a = 1,\ \dot b = 0\) gives \(\partial r/\partial a = b\cos a = 1.755\), exact.
  • Reseed with \(\dot b = 1\) for \(\partial r/\partial b\). One sweep per input, so \(n\) inputs cost \(n\) sweeps.

Reverse mode: one scan down, one scan back

  • Scan forward and store every value. That store is the tape.
  • Scan back from \(\bar r = 1\), accumulating into whatever fed each step.
  • \(b\) is used twice, so \(\bar b\) adds two terms: \(4.000 + 0.479\). Hence \(\mathrel{+}=\), not \(=\).
  • One scan returns \(\bar a\) and \(\bar b\). Forward mode needed two.
Act 5 / Notation

Why a bar, and why \(\mathrel{+}=\)

The bar is a definition. For any variable \(v\) in the graph,

$$\bar v \;=\; \frac{\partial r}{\partial v}$$

so the seed at the output end is simply

$$\bar r \;=\; \frac{\partial r}{\partial r} \;=\; 1.$$

Take the first step back, \(r = w_1 + w_2\). Holding \(w_2\) fixed,

$$\frac{\partial r}{\partial w_1} = \frac{\partial}{\partial w_1}(w_1 + w_2) = 1 + 0 = 1,$$

and the chain rule hands that local slope the sensitivity already accumulated at \(r\):

$$\bar w_1 \mathrel{+}= \bar r \cdot \frac{\partial r}{\partial w_1} = 1 \cdot 1 = 1.$$

An adjoint starts at \(0\) and accumulates: one term per path, summed.

Act 5 / The adjoint rule

One rule runs the whole backward scan

$$\bar u \;=\; \sum_{v \,\in\, \mathrm{children}(u)} \bar v \,\frac{\partial v}{\partial u}$$

How much \(u\) moves the output is set by two things: how much each child moves the output, and how much \(u\) moves that child. Walk the tape in reverse and apply this at every step.

The price is the tape: every intermediate value has to survive until the backward scan asks for it.

Act 5 / The backward sweep

Four steps, five accumulations

fromlocal derivativeaccumulaterunning value
\(r = w_1 + w_2\)\(\partial r/\partial w_1 = \partial r/\partial w_2 = 1\)\(\bar w_1 \mathrel{+}= \bar r,\quad \bar w_2 \mathrel{+}= \bar r\)\(\bar w_1 = \bar w_2 = 1\)
\(w_2 = b^2\)\(\partial w_2/\partial b = 2b\)\(\bar b \mathrel{+}= \bar w_2 \cdot 2b\)\(\bar b = 2b\)
\(w_1 = b\,w_0\)\(\partial w_1/\partial w_0 = b\)\(\bar w_0 \mathrel{+}= \bar w_1 \cdot b\)\(\bar w_0 = b\)
\(w_1 = b\,w_0\)\(\partial w_1/\partial b = w_0\)\(\bar b \mathrel{+}= \bar w_1 \cdot w_0\)\(\bar b = 2b + \sin a\)
\(w_0 = \sin a\)\(\partial w_0/\partial a = \cos a\)\(\bar a \mathrel{+}= \bar w_0 \cos a\)\(\bar a = b\cos a\)

Rows two and four are both \(b\): one contribution per place \(b\) appears, summed by the \(\mathrel{+}=\).

Act 5 / The result

Both derivatives, one sweep

$$\bar a = \frac{\partial r}{\partial a} = b\cos a = 1.755 \qquad \bar b = \frac{\partial r}{\partial b} = 2b + \sin a = 4.479$$

Nothing was approximated, so these agree with differentiating \(f\) by hand to the last digit a float can hold. Forward mode reached the same pair, but it needed one sweep for each.

Seed once at the output, sweep back once, and the number of inputs does not enter the cost.

Seeds, columns and rows

  • Four inputs, two outputs, eight Jacobian entries to fill.
  • Forward seeds an input and fills a column: four sweeps.
  • Reverse seeds an output and fills a row: two sweeps.
  • Training is the extreme case: one loss, millions of parameters, one scan.

Act 5 / In code

What loss.backward() does

a = torch.tensor(0.5, requires_grad=True)
b = torch.tensor(2.0, requires_grad=True)
r = b * torch.sin(a) + b**2   # forward scan: this builds the tape
r.backward()                  # backward scan, seeded with r_bar = 1
print(a.grad, b.grad)         # tensor(1.7552) tensor(4.4794)

requires_grad is what puts a value on the tape. backward() walks it in reverse and accumulates each adjoint into .grad, which is why you must zero the gradients between steps.

The same two numbers as the clip, and no formula for \(\partial r/\partial b\) was written down by anyone.
